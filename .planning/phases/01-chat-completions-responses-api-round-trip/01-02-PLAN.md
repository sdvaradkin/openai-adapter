    **src/translation/index.ts**: Add exports for the response-to-chat translation module:
    ```
    // Response → Chat translation
    export * from './response-to-chat/types.js';
    export * from './response-to-chat/response.js';
    export { translateResponseApiToChatResponse } from './response-to-chat/response.js';
    ```

    **src/handlers/routing.handler.ts**: Modify the chat_completions→response translation branch to intercept and translate the upstream response. The current code calls `passThroughHandler(translatedRequest, reply)` which forwards the response as-is. Change this to:

    1. Import `translateResponseApiToChatResponse` from `'../translation/index.js'`
    2. After the request translation succeeds, do NOT call `passThroughHandler` directly. Instead:
       a. Build the upstream URL: `${config.targetUrl.replace(/\/$/, '')}/v1/responses`
       b. Forward headers from `request.headers` (skip host, content-length, transfer-encoding — same logic as pass-through handler)
       c. Create abort controller with `config.upstreamTimeoutSeconds * 1000` timeout
       d. Fetch upstream: `fetch(upstreamUrl, { method: 'POST', headers: forwardedHeaders, body: JSON.stringify(translationResult.translated), signal })`
       e. Read response text: `await upstreamResponse.text()`
       f. Parse response body: `const parsedBody = JSON.parse(responseText)` — wrap in try/catch, return 502 if JSON parse fails
       g. Call `translateResponseApiToChatResponse(parsedBody)` — store result as `responseToChatResult` — wrap in try/catch
       h. If translation fails: log warning with action `response_translation_failed`, return 502 with `{ error: 'Bad Gateway', message: 'Failed to translate upstream response' }`
       i. Forward upstream response headers to reply (call `reply.header(key, value)` for each)
       j. Return `reply.code(upstreamResponse.status).type('application/json').send(JSON.stringify(responseToChatResult.translated))`

       Note on naming: use `chatTranslationResult` for the request translation result and `responseToChatResult` for the response translation result to avoid name collision with the existing `translationResult` variable.

    **Key constraint**: Keep the pass-through handler calls for the non-translation path unchanged. Only the `chat_completions → response` branch changes. The pass-through handler can still be used for future reference but this branch now has its own fetch + translate cycle.

    Timeout and abort handling: copy the same pattern used in `pass-through.handler.ts` — `setTimeout` with `controller.abort()`, `clearTimeout` in finally block, check `error.name === 'AbortError'` for 504 response.
